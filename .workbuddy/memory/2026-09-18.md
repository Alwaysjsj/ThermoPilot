## 修复：启动后不显示界面（Caliburn.Micro + WPF）

- 现象：ThermoPilotClient 进程正常存活、无异常，但没有任何可见窗口。
- 定位方法：
  - 用 Python ctypes EnumWindows 枚举顶层窗口，发现只有 WPF 内部隐藏窗口
    （`HwndWrapper[...]` 136x38 不可见，经最小 WPF 对照实验证实它属于 WPF 自身，
    不代表业务窗口已创建）。
  - 在 App/Bootstrapper 加临时文件日志，确认 `Application.Startup` 事件已触发，
    但 `Bootstrapper` 构造函数从未执行。
- 根因：`<local:Bootstrapper x:Key="bootstrapper"/>` 写在 App.xaml 的
  `Application.Resources` 里。.NET Core 3.0+ 的 WPF 对 App.xaml 资源字典采用
  延迟实例化，该对象根本不会被构造，Caliburn.Micro 的 OnStartup 因此挂不上。
  这是 .NET Framework 时代 CM 官方示例写法在 .NET (Core) 上的失效点。
- 修复：
  - App.xaml 移除 Bootstrapper 资源，改为在 `App` 构造函数中 `new Bootstrapper()`
    （必须在 `Application.Run()` 之前，才能挂上 Startup 事件）。
  - App 增加全局异常处理：`DispatcherUnhandledException` 弹窗 + 写 `Logs/Crash.log`。
  - `HomeViewModel.DisplayName = "ThermoPilot"`（否则窗口标题是类型全名）。
  - `HomeView` 增加 Width=1280/Height=800/MinWidth=1024/MinHeight=640
    （根视图无固有尺寸时窗口尺寸不可控）。
  - 顺带移除 `RecipeEditView` 构造函数里的 `DataContext = new RecipeEditViewModel()`，
    它会绕开容器再造实例、使 RecipeEditViewModel 的单例注册失效。
- 验证：编译 0 错误；启动后窗口 `ThermoPilot` 正常显示 Recipe 管理界面（已截图）。
- 遗留：右侧按钮列（New/Delete/Edit...）在当前显示器上可能被裁在窗口右缘之外，
  属 RecipeEditView 布局（固定 260+5+*+110 四列）与窗口宽度/DPI 的匹配问题，
  与本次启动 bug 无关；需要时可改为窗口最大化或调整根视图固定宽度。

## 追加：修复「启动窗口非常大」（2026-09-18 下午）

- 背景：期间根视图被重构成 `View/Shell/ShellView.xaml` + `ShellViewModel`
  （HomeViewModel/HomeView 变成遗留代码）。
- 现象：窗口变成 3506 x 601 px，比 2560 宽的主屏还宽 1464px，右侧内容跑到屏幕外。
- 定位：让 WPF 自己报告（在 Bootstrapper.OnStartup 里 `Dispatcher.InvokeAsync`
  打印 `Window.ActualWidth` / `SizeToContent` / `WorkArea` 到文件），拿到硬数据。
- 根因：Caliburn.Micro 创建根窗口时用的是 **`SizeToContent = WidthAndHeight`**，
  窗口会跟着内容"想要"的尺寸走。新的 `ShellView` 没给任何尺寸，而内容区的
  DataGrid 含 `Width="*"` 列，在**无限宽度**下测量时想要的宽度会失控膨胀
  （约 2800 DIP），于是窗口被撑到 3506px。
- 修复：`ShellView.xaml` 加 `Width=1280 Height=800 MinWidth=1024 MinHeight=640`。
  修复后窗口 = 1294 x 838 DIP（内容区正好 1280x800），落在 2048x1104 工作区内。
- **重要更正**：上一节「遗留：右侧按钮列被裁掉」的结论是**错的**，那是截图假象。
  Python 进程 DPI-unaware，PrintWindow 只拿到窗口左上角一块（图像 1294px
  实际只覆盖窗口左侧约 1035 DIP），右侧约 260 DIP 根本没截进来。
  按像素反推（1 图像 px = 1 物理 px = 0.8 DIP）验证："Modified Time" 表头
  预期在 DIP 982 → 物理 1227，实测 1230，完全吻合。布局本身没有问题。
  教训：在 125% 缩放的机器上做像素比对，必须先确认截图工具的 DPI 感知情况，
  或者干脆用 WPF 自己打印 ActualWidth/DesiredSize，不要靠截图像素推断。

## 追加：修复「最大化后内容不铺满」（2026-09-18 下午）

- 现象：上一节把 Width/Height 写死在 ShellView 上之后，窗口点最大化，
  外框是全屏了，但内容只有 1280x800 一块，四周一圈空白。
- 根因：尺寸写死在**根视图**上，根视图就不再随窗口拉伸；
  而窗口本身仍是 CM 默认的 `SizeToContent = WidthAndHeight`。
- 正确做法：尺寸控制应该放在**窗口**这一层。
  新增 `ThermoPilotClient/Services/ShellWindowManager.cs`，
  继承 CM 的 `WindowManager` 并重写 `protected override Window EnsureWindow(...)`，
  对 CM 自动生成的窗口（判断条件：`view is not Window`）设：
  `SizeToContent = Manual` + Width/Height 1280x800 + MinWidth/MinHeight 1024x640
  + `WindowStartupLocation = CenterScreen`。
  在 `Bootstrapper.Configure()` 里把 `IWindowManager` 注册成这个子类。
- 同时把 ShellView.xaml 上的 Width/Height/MinWidth/MinHeight 全部去掉，
  让它恢复可拉伸。
- 实测结果（本机 2560x1440 @125%）：
  - 启动：窗口 1600x1000 物理 = 1280x800 DIP，居中于 (480,190)
  - 最大化：2578x1398，内容（顶栏/状态栏/右侧按钮列）完整铺满
  - `Window.SizeToContent=Manual`，`ShellView.Actual=1265.6x762.4`（填满客户区）

### 复盘要点
- CM 的窗口尺寸策略有两个坑，必须分清楚：
  1. 不给尺寸 → `SizeToContent=WidthAndHeight` 让内容把窗口撑爆；
  2. 把尺寸写在根视图上 → 窗口能正常开启，但最大化时内容不跟着拉伸。
  正解是覆盖 WindowManager、把 `SizeToContent` 改成 `Manual`。
- 给 `WindowManager` 加行为只需重写 `EnsureWindow`，签名是
  `protected virtual Window EnsureWindow(object model, object view, bool isDialog)`，
  CM 4.0.212 上编译可直接验证。
